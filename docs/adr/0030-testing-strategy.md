# ADR 0030: Testing strategy

Status: accepted | Last updated: 2026-10-04 | Register: D-058

## Context

Correctness depends on reproducing game semantics without shipping game data (R11), and performance budgets were measured in a spike that must not regress.

## Decision

Rust tests use cargo-nextest, proptest, rstest, assert_fs and goldenfile with JSON goldens only; criterion benches are checked against `xtask/budgets.jsonc` and a 2 times regression fails; golden output must be identical at 1 and 8 threads. Frontend uses Vitest 5 and Playwright with `mockIPC` on every pull request, plus WebdriverIO smoke nightly behind the `e2e` feature, which release builds are verified to lack. Fixtures are synthetic or generated by `rimstudio-testing`; vectors use fictional numbers; tests against a real install are `#[ignore]` with an environment variable.

Golden files are JSON, which keeps R10 intact and makes diffs readable in review. Benchmarks run on one reference machine per OS in CI and on the developer machine for real installs; a budget change needs a justification line in the same commit.

## Consequences

- Contributors without RimWorld can run the suite.
- Real-data checks run on the owner's machine only.
- Gallery screenshots catch visual regressions in both themes.

## Alternatives rejected

- insta snapshots in other formats.
- divan.

# ADR 0022: Typed bindings generator and DTO conventions

Status: accepted | Last updated: 2026-10-04 | Register: D-042, D-043

## Context

The frontend must call Rust commands type-safely (R1). tauri-specta stable 1.0.2 targets Tauri 1 only; the 2.0.0 line is a release candidate. GitButler and Yaak both commit generated output. 64-bit ids exceed JavaScript's safe integers.

## Decision

Bindings come from `tauri-specta =2.0.0-rc.25` with `specta-typescript =0.0.12`, pinned exactly, output committed to `packages/ipc-types/src/bindings.ts` and drift-checked. The fallback is ts-rs 12.0.1 with a typed invoke map generated by xtask from the registry; the switch happens if the release candidate breaks on a Tauri bump or spike S-01 fails. DTOs are plain serde structs in `rimstudio-ipc-types` so both generators work. Conventions: `<Command>Request` and `<Command>Response`, camelCase fields, kebab-case enum strings, 64-bit ids as strings, and list rows carry list columns only (3000 slim records cost about 8 ms).

## Consequences

- S-01 is an M0 gate and must confirm macro-generated commands and `ipc::Response`.
- Domain types keep their own serde casing and are never exposed directly.
- Drift between Rust and TypeScript fails CI (invariant I-19).

## Alternatives rejected

- JSON Schema route.
- Hand-written types.
- taurpc and typegen: immature.

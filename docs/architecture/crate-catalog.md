# RimStudio crate catalog

This catalogue describes every crate and binary in the RimStudio Cargo workspace: layer, purpose, public API sketch, internal and external dependencies with pinned versions, features, error type, tests and benchmarks, the research notes that govern it, and its milestone. There are 24 workspace members: 22 library and binary crates under `crates/` (including `rimstudio-testing`), the Tauri shell under `apps/desktop/src-tauri`, and `xtask`. API sketches show types, traits and signatures, not implementations. For the crates built for 0.1.0 (core, xml, io, platform, xpath, defs, design, steam, library, workspace, manager, toolkit, ipc-types, testing) the sketch is the shape as built and the source is authoritative; for the others it is the intended shape that the first implementation may refine without changing the layer or dependency edges. Dependency lists of built crates are the 0.1.0 manifests; edges that a later feature needs are added with it. The directory tree is in [workspace layout](workspace-layout.md), the edge rules in its section 4, the invariants (I-01 to I-19) in the [architecture overview](overview.md) and the reasons behind each choice in the [decision register](decision-register.md).

Milestone numbering follows the [roadmap, section 1.1](../roadmap.md#11-mapping-to-the-milestone-names-in-the-register) (older mentions of M3 to M6 use the decision register's numbering).

Milestones follow the [roadmap](../roadmap.md): M0 skeleton, M1 core engine, M2 manager MVP, M3 manager v1, M4 toolkit foundation, M5 item designer, M6 Workshop publishing, M7 polish and release. A crate's first milestone is when its first real code lands; the roadmap owns sizes and exit criteria.

## 2. Granularity decisions

The target was 16 to 24 members. The workspace has 24 including three binaries and two support crates. Each split is justified by at least one of: dependency enforcement (a third party crate or an OS confined to one crate), compile time (heavy or rarely changing code isolated from hot code), testability (pure code that can be benchmarked and fuzzed without IO).

| Split | Reason |
|---|---|
| `xml` separate from `io` | enforcement of I-02 (one parser crate, one wrapper entry in `deny.toml`) |
| `io` and `platform` separate | `platform` is the only crate with `cfg(target_os)` (I-11); `io` is portable and testable on any runner |
| `xpath` separate from `defs` | compile time (stable, rarely changed), a corpus coverage gate of its own and a fuzzable pure interface |
| `defs`, `rules`, `sort`, `validate`, `design` separate engines | no IO, so each is benchmarked in memory; `sort` and `validate` have different budgets (on demand versus every list edit) and different callers (CLI `check`) |
| `steam`, `library`, `workspace`, `datasets` separate services | different dependency sets: `datasets` owns the HTTP client, `workspace` owns the def engine linkage, `library` must not depend on `defs`, `steam` has no IO of its own |
| `manager`, `toolkit`, `publish` separate features | I-08 (no edges between features) and independent compile and test cycles |
| `ipc-types` separate | Tauri-free DTOs shared by app, shell, CLI and the helper |
| `app` separate from `shell` | the only way to give the CLI the same handlers without feature flags on the shell (D-006, D-007) |
| `shell`, `cli`, `steam-helper` separate | three processes with three dependency worlds (Tauri, none, Valve) |

Kept as modules and split later, with the trigger that would justify it:

| Module | Lives in | Split when |
|---|---|---|
| `tree` (node tree and arena) | `core` | `xpath` is reused outside RimStudio, or `core` exceeds about 8,000 lines |
| `ce` (CE reader, formulas, patch generator, lint) | `design` | the CE patch generator for existing mods (after M5) lands, becoming `rimstudio-ce` shared by two features |
| helper `proto` types | `ipc-types` | the helper binary size or compile time is hurt by DTO derives |
| `net` (HTTP) | `datasets` | a second HTTP consumer appears (Workshop metadata, update checks) |
| `deploy` (link farm, ModsConfig) | `library` | deployment gains its own dependencies or exceeds about 4,000 lines; candidate name `rimstudio-deploy` |
| `logs` (log classification) | `validate` | log tooling needs streaming dependencies not wanted by list validation |
| `rimsort` (import) | `datasets` | the foreign database reader needs more than one module |
| `store` and `fs` | `io` | `notify`, `ignore` compile time hurts crates that only need JSON; candidates `rimstudio-store`, `rimstudio-fs` |
| `texture` tool | `toolkit` | it takes a DDS encoder dependency; then it becomes `rimstudio-tool-texture` |
| `bisect` | `manager` | it grows its own game-run orchestration |

## 3. Foundation crates

### rimstudio-core

Layer `l0-domain`, lib, M0. Pure data types and helpers; no IO, no async runtime, no OS access.

- **Purpose**: the vocabulary all crates share, and the port traits that keep the OS out of everything else.
- **Public API sketch** (as built; the source is authoritative):
  - `ids`: `PackageId` (lowercased for comparison, original kept for display), `ModId` (`w<workshopId>` or `<source>:<packageId>`), `WorkshopId(u64)` serialised as a string, `ModIdx(u32)` and `FileId(u32)` (session local handles), `SourceId`, `ProfileId`, `ProjectId` (the workspace crate derives it as `p-<8 hex>` from the normalised folder path, because the id type disallows dots), `JobId`.
  - `version`: `GameVersion { raw, major, minor, build, rev }` with `parse("1.6.4871 rev598")`; `supported_matches(&[String]) -> bool` using exact `major.minor` after stripping `v`.
  - `tree`: `Node { tag, attrs: Vec<(String, String)>, children: Vec<Child> }`, `Child::{Element(Node), Text(String)}`, `OriginId`, `ArenaDoc` with parent and sibling links, `NodeBuilder`; JSON shape identical to the def engine vectors.
  - `diag`: `Diagnostic { code, severity, mod_idx, file, message, span, args }` (the field pointer of a content problem travels in `args["field"]`, `FIELD_ARG`), `DiagCode`, `Severity`, `DiagSink` (counts per code, keeps the first 100 samples), `DiagnosticSummary`.
  - `mods`: `ModMeta::new(PackageId, name, SourceId, path)` with public fields; relation lists (`loadAfter`, `incompatibleWith` and the rest) are `Vec<String>` because About.xml may hold invalid ids, and `by_version: BTreeMap<String, VersionRelations>`; `effective_load_after/before/force_*/incompatible_with(&GameVersion)` and `effective_dependencies` add the matching `ByVersion` block to the base list. `ModIndex::builder().push(..).build()` sorts by lowercase package id, then source id, then path, so `ModIdx` values do not depend on scan order; lookups `get`, `iter`, `by_mod_id`, `by_package_id` (any case) and `first_by_package_id`. `ActiveSet` (trimmed lowercase text with one trailing `_steam` removed, empty never matches) and `ActiveList` (duplicates dropped ignoring case). `SourceKind::{GameData, GameMods, Workshop, Custom}`, `ModSource`, `SourceSet`.
  - `load_plan`: `LoadFoldersSpec`, `LoadPlan`, `resolve_load_folders(&ModMeta, &GameVersion, &ActiveSet) -> LoadPlan` (an empty chosen version block loads nothing, as the game picks the greatest older key by string order), `collect_files(&LoadPlan, Subdir, &dyn Listing) -> Vec<SourceFileRef>`.
  - `ports` (all `Send + Sync` and object safe): `Clock`, `EnvProbe` (`var`, `home_dir`, `exe_dir`, `locale`), `RegistryProbe`, `FsProbe` (every call takes a `Duration` deadline and returns `PortResult`; `volume_class` classifies Fat, Exfat, Ntfs, Posix, Unknown), `ProcessProbe`, `LinkBackend`, `Launcher`, `CredentialStore`, `SandboxProbe`, `InstallSourceProbe`; `DetectEnv` is a trait with four accessors (`clock`, `env`, `registry`, `fs`) and `DetectEnvRef` is a ready made struct of four references. Data types: `PortError { kind, message }` with codes `port.not-found`, `port.permission-denied`, `port.timed-out`, `port.unsupported`, `port.io`; `PlatformDirs { config, data, cache, logs, state }` lives here and is used as is by `rimstudio-io`; `FsMeta`, `VolumeClass`, `LinkKind`, `LaunchSpec`, `InstallSource`. Paths are `Utf8Path` everywhere.
  - `settings`: `Settings` and `WorkspaceSettings` (serde camelCase, kebab-case enums; a section equal to its default is not written; unknown top level keys are kept in `extra`), `CustomFolder { id, path, label, enabled, layout, scan_depth, watch: Option<bool>, priority: Option<i32>, read_only, link, volume_hint, colour, extra }` (layout is kebab-case `auto`, `mods-root`, `single-mod`; the camel spellings `modsRoot` and `singleMod` are accepted on read; `watch_enabled(local)` and `to_source(position)` resolve the optional defaults), `validate()` returning `SettingProblem`s, `normalize_path`, `path_relation`, `validate_custom_folders`, the `*_SCHEMA_VERSION` constants.
  - `jobs`: `Progress`, `ProgressSink`, `CancelToken` (`Arc<AtomicBool>`).
  - `paths`: RimWorld path constants (`ABOUT_XML`, `MODS_CONFIG`, ...); `os`: `Os::current()`; `redact`: `Redactor` (home folder, user directories, user name, key=value secrets, bearer tokens, 64 bit Steam ids and long token-like runs; `steam_id_tag`).
- **Internal dependencies**: none.
- **External dependencies**: `serde` 1.0.229, `serde_json` 1.0.151, `camino` 1.2.6 (serde1), `thiserror` 2.0.21, `rustc-hash` 2.1.3, `blake3` 1.8.7 (ids).
- **Features**: none. The optional `schema` feature (schemars derives) is not implemented; JSON Schemas are produced by `xtask` when they are needed.
- **Error type**: `CoreError` (invalid id, unparseable version, invalid load folders spec); content problems are `Diagnostic`.
- **Tests and benchmarks**: proptest on id normalisation and version parsing and a reference model property test of the arena (`tests/arena_model.rs`); rstest tables for `supported_matches`; load-plan tests built from the corpus signatures (195 structural variants); node tree JSON round trip against the def engine vectors. 333 tests, no benchmarks.
- **Governing research**: [mod format and corpus](../research/rimworld-mod-format-and-corpus.md), [def engine semantics](../research/def-engine-semantics.md) (node shape), [steam and detection](../research/steam-and-game-detection.md) (custom folder model), [settings catalogue](../research/rimsort-settings-catalog.md), [core domain](../research/rimsort-core-domain.md).

### rimstudio-xml

Layer `l1-infra`, lib, M1. The single XML boundary (I-02).

- **Purpose**: parse RimWorld XML into node trees, render node trees to XML, edit existing files by byte span, and provide typed codecs for the few RimWorld files RimStudio reads or writes.
- **Public API sketch** (as built):
  - `ParseMode::{Game, Tolerant}`; `parse_document(bytes, mode) -> XmlResult<ParsedDoc>` where `ParsedDoc { root: Node, diagnostics }`. Game mode matches the game's loader (BOM stripped, UTF-8 forced, comments and whitespace-only text dropped except under `xml:space="preserve"`, DTD rejected, illegal characters tolerated); Tolerant mode recovers with warnings and fails only without any root (it stops at the first syntax error and closes open elements). `reader::parse_top_level(bytes, mode, expected_root)` returns the top-level children of a `Defs` or `Patch` file with an `xml.unexpected-root` warning.
  - `render(&Node, &RenderOpts) -> String` (never fails: control characters become numeric references, U+0000 is dropped), `try_render` (validates names), `render_defs_file`, `render_patch_file`, `render_list_file(root_tag, &[Section], ..)` with `Section { comment, nodes }` for comment headed groups. `RenderOpts { indent, eol, declaration, bom, final_newline, self_close_empty, blank_line_between_top_level }`; the default is 2 spaces, LF, declaration, no BOM; `RenderOpts::fragment()` has no declaration or final newline. Attribute order is the stored order.
  - `edit::SpanEditor::open(text) -> XmlResult<SpanEditor>` (the text may be malformed) with a read side (`children`, `element`, `attr`, `eol`, `indent_unit`, paths such as `/loadFolders/v1.6/li[2]`, `*` wildcard) and splice edits (`replace_text`, `replace_children`, `insert_child`, `insert_child_at`, `insert_before`, `insert_after`, `replace_element`, `remove`, `set_attr`, `remove_attr`); each edit mutates the editor, returns `XmlResult<&str>` (the new text), matches sibling indentation and the document's line ending, and leaves the text untouched on failure; `into_text()` consumes it. Bytes outside the changed span are untouched.
  - `about::read_lenient(bytes) -> AboutRead { about, parsed, warnings }` (never fails; an unreadable file gives the default `About` and `parsed = false`). Field names are matched case sensitively like the game; a case variant gives `about.tag-case` and is ignored unless `AboutOptions::case_insensitive_fields` is set. Every field but the description is trimmed; a comment or child element inside a text field drops the value (game behaviour). `About::into_meta(source, path)` builds the core `ModMeta`. Field edits over text: `set_package_id`, `set_name`, `set_description`, `set_supported_versions`, `set_load_after`, `add_load_after`, `add_supported_version` (add is idempotent ignoring case). `AboutSpec`, `create_about`, `render_about` write a new About.xml.
  - `load_folders::{read, create, add_entry, gate_folder, remove_entry, ensure_block}`: `read` is tolerant, treats whitespace-only entry text as the mod root and returns an error only without a root; block elements are written as `v<key>` for numeric keys; `add_entry` is idempotent; `gate_folder` adds an `IfModActive` list; `ensure_block` copies the nearest lower block, else the default, else a fallback.
  - `mods_config::{read, write_active(original, &ModsConfigData), create}`: `write_active` replaces only `activeMods` (plus `version` or `knownExpansions` when given) and keeps unknown parts, comments and the line ending; `known_expansions` is `Option<Vec<String>>` and `None` means absent. `save_meta::read_meta(impl Read)` stops after `</meta>` (limit 4 MiB).
  - `defs_scan::{index_file(bytes) -> Vec<DefIndexRecord>, index_file_detailed}`: streaming, quick-xml, no tree, not a validator; an early end gives the records so far plus the error in the detailed form. `patches::{parse_patch_file(bytes) -> XmlResult<Vec<Node>>, parse_patch_file_with(bytes, ParseMode)}` return operations as opaque nodes; a file the game would skip is an error.
- **Internal dependencies**: `rimstudio-core`.
- **External dependencies**: `quick-xml` 0.42.0, `thiserror` 2.0.21, `serde` 1.0.229, `camino` 1.2.6.
- **Features**: none. (The optional memchr structural scanner of the scan spike is added only behind a conformance test and is not planned for M1.)
- **Error type**: `XmlError` (`code()`: `xml.parse`, `xml.dtd-rejected`, `xml.no-root`, `xml.too-deep`, `xml.edit-path-missing`, `xml.edit-path-invalid`, `xml.edit-unsupported`, `xml.invalid-value`, `xml.io`; `to_diagnostic()`), and diagnostic codes under `xml.*` for recovered problems.
- **Tests and benchmarks**: BOM, CDATA, DTD, invalid character and encoding cases; byte-preservation test (edit `packageId` in a fixture with comments and compare bytes outside the span); render then parse equals identity on node trees (proptest); golden XML for templates; differential run of the indexer on real corpora when a path is configured (`#[ignore]`). Benches: `about_parse` (budget: 690 files under 10 ms parallel), `def_index` (budget 300 ms for 23,717 files warm; measured 125 ms).
- **Governing research**: [rust crate research](../research/rust-crate-research.md) section 4, [scan performance spike](../research/scan-performance-spike.md) (S2, S3), [def engine semantics](../research/def-engine-semantics.md) implication 1, [CE patch conventions](../research/ce-patch-conventions.md) implication 11.

### rimstudio-io

Layer `l1-infra`, lib, M0. Everything that touches the filesystem for storage, walking and watching. Candidate to split into `store` and `fs`.

- **Purpose**: durable, versioned, comment-preserving app data and the scanning primitives, with the only code allowed to write files.
- **Public API sketch** (as built):
  - `roots::DataRoots { config, data, cache, logs, portable }`; `resolve(&PlatformDirs, &dyn EnvProbe, &dyn FsProbe)` and a pure `resolve_with(.., marker_exists)`. `PlatformDirs` is the core port type (it is not redeclared here); the exe folder comes from `EnvProbe::exe_dir` and `APPIMAGE` from `EnvProbe::var`. The portable marker `rimstudio.portable` moves all roots under `<base>/data/{config,data,cache,logs}`. `RootKind::{Config, Data, Cache, Logs}`.
  - `schema::Versioned { const KIND; const VERSION; fn migrations() }` (the defaulted, additive `migrations()` supplies forward steps; there is no global register function). `Store<T: Versioned>`: `Store::open(&DataRoots, RootKind, name, Arc<dyn Clock>)` or `Store::at(path, clock)`, then `load() -> Loaded<T>` (infallible: it returns the file, a migrated copy, the newest readable backup or the default, with `LoadOrigin` and an optional `LoadProblem { code, message, line, column }`, and `read_only` when the file is newer than the app), `save(&T)`, and `edit(|&JsoncEditor| ..)` for comment preserving edits through the CST; `store::edit_jsonc(path, &BackupPolicy, &dyn Clock, edit_fn, verify_fn)`. A corrupt hand edited JSONC file is never moved or overwritten: loading falls back to a backup or the default, saving is blocked and the line and column are reported.
  - `jsonc::JsoncEditor`: `get`, `set(&[&str], &Value)`, `insert_at`, `remove`, `push`, `remove_by_id`, `upsert_by_id`, `sync_with`, `to_value`, `finish`; `jsonc::{parse_value, from_str, to_json_bytes, render_new(header, &Value)}`. The edit path is the tested subset of the `jsonc-parser` CST described in [data and persistence](data-and-persistence.md) section 9 (spike S-02).
  - `collection::Collection<T: Versioned>` (the in house JSON database, D-083, [ADR 0035](../adr/0035-in-house-json-database.md)): a directory of documents, one JSON file per id, each in the envelope `{kind, v, data}`. `Collection::open(&DataRoots, RootKind, name, Arc<dyn Clock>)` or `open_dir(dir, clock)`; `put(id, &T)` (atomic, verified, per document backup), `get(id) -> Result<Option<Loaded<T>>>` (forward migrations, newer documents reported read only), `delete`, `exists`, `len`, `list_ids()`, `scan()`, `list_summaries() -> Vec<IndexEntry { id, v, size, summary }>` where `summary` is a JSON value built by an optional `with_summarizer`, `rebuild_index()`, `quarantined() -> Vec<QuarantineEntry>`. `Clone` is cheap and shares the lock and index. Reserved names in a collection folder: `index.json`, `.quarantine/`, `.backups/`, `.lock` and the unused `.journal`; the id `index` is rejected. No cross process lock (the `.lock` file is informational). No SQL and no other storage engine.
  - `atomic::atomic_write(path, bytes)` (temp file, fsync, rename, directory fsync, creates parents) and `atomic_write_with(&dyn FsOps, ..)` with an aside rename fallback; `backup::{BackupPolicy { keep_last, keep_all_today, daily_window_days, skip_identical, root }, user_data(), light(), rotate(path, &policy, &dyn Clock), list_backups, select_keep, keep_pre_migration}`.
  - `migrate::{MigrationFn, MigrationRegistry}`: pure `fn(serde_json::Value) -> Result<Value, MigrateError>`, forward only, an instance registry shared by `Store` and `Collection`.
  - `walk::{list_mod_roots, scan_parallel}` (purpose built `rayon` recursion over `read_dir` and `DirEntry::file_type`, 1 to 8 workers, links reported and not followed, output sorted by relative path), `statkey::{StatKey { rel_path, size, mtime_ns, file_id }, FatPolicy, KeyVerdict, hash_file}`; `file_id` is filled only through an injected `FileIdFn` hook because `cfg(unix)` and `cfg(windows)` are quarantined in `rimstudio-platform` (I-11).
  - `rename::{move_path, move_path_with, copy_verify_remove, remove_file, remove_empty_dir, MoveOutcome}` (a guarded move of a file or folder that never overwrites, with a verified copy across volumes, used by the layout fixes).
  - `copy::{read_source, hash_existing, copy_verified, SourceBytes, CopyReport, CopyError}` (a guarded copy of an imported texture or sound clip: the source is a regular file read under a byte limit, never a link, hashed with SHA-256 and compared with the hash the plan holds; the target is written atomically and read back) and `sha256::{Sha256, sha256_hex, to_hex}` (the in house FIPS 180-4 implementation; the workspace has no SHA-2 dependency).
  - `guard::{RootGuard::{check, validate}, sanitize_name, to_safe_component, lexical_clean}`, `fence::{GameWriteFence, FenceOp, FenceConfig, OwnedEntry}` (two allow lists, see I-05), `real_fs::RealFs` implementing `FsProbe` (deadline through a helper thread; volume class read from `/proc/self/mountinfo` when it exists). `watch` and `ignore_set` are empty deferred modules (`notify`, `notify-debouncer-mini` and `ignore` stay declared but unused).
- **Internal dependencies**: `rimstudio-core`.
- **External dependencies**: `serde_json` 1.0.151 (`preserve_order`), `serde_path_to_error` 0.1.20, `jsonc-parser` 0.34.0 (`serde`, `cst`, and its `serde_json` feature for `CstNode::to_serde_value`), `atomic-write-file` 0.3.1, `tempfile` 3.27.0, `fs-err` 3.3.2, `rayon` 1.12.0, `notify` 8.2.0, `notify-debouncer-mini` 0.7.0, `ignore` 0.4.33 (the last three unused until the watcher lands), `same-file` 1.0.6, `dunce` 1.0.5, `blake3` 1.8.7, `camino` 1.2.6, `tracing` 0.1.44, `thiserror` 2.0.21. `trash` is not used.
- **Features**: none.
- **Error type**: `IoError` with `StoreError`, `MigrateError`, `GuardError` variants; codes such as `store.io`, `store.parse`, `store.document-corrupt`, `store.newer-than-app`, `store.id-invalid`, `store.write-blocked`, `io.write-verify-failed`, `io.path-outside-roots`, `guard.*`, `fence.refused`, `migrate.*`.
- **Tests and benchmarks**: change one setting and assert comments elsewhere are byte-identical; crash injection at each step of write and backup; migration fixtures of every historical version; injected-clock backup retention; stat key simulation of 2 second and 1 hour shifts; `ENOSPC` fallback; fence refusal tests with a recording filesystem. Benches: `walk_scan` (budget: pruned scan of 697 mods under 50 ms warm), `manifest_io` (load under 50 ms for the compact layout).
- **Governing research**: [rust crate research](../research/rust-crate-research.md) sections 5 and 6, [scan performance spike](../research/scan-performance-spike.md), [packaging research](../research/cross-platform-packaging-research.md) implications 6 and 8, [settings catalogue](../research/rimsort-settings-catalog.md).
- **Spike S-02**: done, see [data and persistence](data-and-persistence.md) section 9 for the CST findings.

### rimstudio-platform

Layer `l1-infra`, lib, M1. The only crate with `cfg(target_os)` (I-11).

- **Purpose**: implement every port of `rimstudio-core::ports` for the running operating system.
- **Public API sketch** (as built): `SystemPlatform::new()` (a `Copy` value) implements `Clock`, `EnvProbe`, `RegistryProbe` (real on Windows through `winreg`, `None` elsewhere), `ProcessProbe::running(&[&str]) -> Vec<RunningProcess>` (Linux scans `/proc`, macOS parses `ps`, Windows parses `tasklist`), `LinkBackend` (`create_dir_link(target, link) -> LinkKind`, `remove_link`, `is_link`, `read_link`, `support() -> LinkSupport { symlink, junction, needs_privilege }`; on Windows it reports symlink true, junction false, needs privilege true and always creates a symlink, because no junction crate is used), `Launcher::spawn(&LaunchSpec) -> PortResult<ChildHandle>` (the only place an application process is spawned; `steam://` URLs only, restricted character set), `CredentialStore` (always `port.unsupported`; the `keyring` crate is not used), `SandboxProbe`, `InstallSourceProbe`. It does not implement `FsProbe`: the real one is `rimstudio-io::real_fs::RealFs`. ## 4. Engines (pure)

### rimstudio-xpath

Layer `l2-engine`, lib, M1.

- **Purpose**: XPath 1.0 parse and evaluate over `ArenaDoc` with the semantics the game's runtime has, plus index hints.
- **Public API sketch** (as built): `XPath::parse(&str) -> Result<XPath, XPathError>` (whitespace and newlines trimmed; full XPath 1.0 grammar; unknown functions, wrong arity, variables and prefixed names are rejected at parse time as the game does; `parser::parse` is the lower level pure grammar); `select(&self, &ArenaDoc)` (document node as context, document order, no duplicates, `Err(AttributeResult)` when the result holds attribute nodes) and `select_from(.., NodeId)`; `select_nodes(.., NodeId) -> Vec<XNode>` where `XNode::{Node(NodeId), Attr { owner, index }}` also returns attributes; `eval(&self, &ArenaDoc, NodeId) -> Result<Value, XPathError>` and `eval_document` with exact XPath 1.0 coercions (`Value::{NodeSet, String, Number, Boolean}`); `index_hint() -> Option<IndexHint>` with `IndexHint::{DefByName { def_type, name }, DefsByNames(Vec<DefKey>)}` for whole expressions of the shape `Defs/Type[defName='x']` (or chains and unions of them), and `index_plan() -> Option<IndexPlan { hint, rest }>` plus `select_with_defs(&ArenaDoc, &[NodeId])` for the common `Defs/Type[defName='x']/trailing/steps` shape, so a caller that owns a def index can skip the full evaluation. The namespace axis and `lang()` parse but evaluate to `UnsupportedAxis` and `Unsupported`; `id()` yields the empty set. Operator chains are flat in the AST, nesting is limited to 64 levels at parse (`xpath.too-deep`) and evaluation has a depth guard of 1024.
- **Internal dependencies**: `rimstudio-core`.
- **External dependencies**: `thiserror` 2.0.21.
- **Features**: none.
- **Error type**: `XPathError` (non exhaustive; codes `xpath.parse`, `xpath.unknown-function`, `xpath.arity`, `xpath.unbound-prefix`, `xpath.unbound-variable`, `xpath.type`, `xpath.not-node-set`, `xpath.attribute-result`, `xpath.unsupported-axis`, `xpath.unsupported`, `xpath.too-deep`, `xpath.stale-context`).
- **Tests and benchmarks**: one fixture per coercion row of the XPath note; the corpus gate is a hand written table in `tests/corpus.rs` weighted by the tier occurrence counts (the raw expression list is not in the repository): tier B at least 97 percent of occurrences, tier C at least 99.8 percent; properties checking document order and parse then print then parse identity. Expected node counts come from fictional documents worked out by hand; no oracle outputs or golden hashes from Mono or libxml2 are stored. Bench: `ce_ops` (2,849 operations, budget under 2 s together with `defs`).
- **Governing research**: [XPath coverage](../research/xpath-patch-coverage.md), [def engine semantics](../research/def-engine-semantics.md) implication 6.

  - `Ctx::new(&DataRoots, &dyn DetectEnv, &dyn FsProbe, &dyn Clock)` with public fields and builders `with_os`, `with_mods_config_version(fn(&str) -> Option<String>)`, `with_scan_fs(Arc<dyn FsProbe>)`, `with_file_id`. The application must supply `scan_fs` (a `RealFs`) and the platform `FileIdFn`, otherwise scans never take the FAT hash path, and `mods_config_version` for the `ModsConfig.xml` version warning.
  - `settings::{get(ctx, SettingsGetRequest) -> SettingsView, update(ctx, SettingsUpdateRequest { patches }) -> SettingsView}`: first run writes a commented `settings.jsonc`; updates are section patches (merge patch, `null` resets); every changed leaf is written as a minimal comment preserving edit through `Store::edit`, defaults are never written; unknown sections or keys, invalid values and syntax-error or newer-version files are refused without writing. `SettingsView { settings, effective, problems, file_problem, origin, stored_schema_version, read_only, created, path, rev }` where `effective` holds full section values (an invalid stored section reads as the default there while the file keeps the value) and `rev` is a fingerprint. `settings.jsonc` holds only the app settings; custom folders and path overrides live in `workspace.jsonc` (see [settings](../features/settings.md)).
  - `detect::{run(ctx, DetectRunRequest) -> DetectRunResponse, get_report, set_override(ctx, DetectSetOverrideRequest { field: OverrideField::{GameInstall, UserDir, SteamRoot, WorkshopDir}, path, pinned }), select_install, is_game_install}`: runs the `rimstudio-steam` locator and caches the report as JSON (`detection-report.json` in the data root); an override is validated, stored in `workspace.jsonc` and detection is rerun; a `None` path clears it; a `WorkshopDir` override is added to `paths.extraWorkshopDirs` and `effective_sources` appends those directories as `workshop-N` sources. The cached report is reused until `detect_run`, `set_override` or a full scan.
  - `sources::{list, add_folder, update, remove, probe_folder, effective_sources}`: overlaps are refused as nested, duplicate, enclosing, inside the game `Mods` folder or a symlink to a known source; removing a folder only edits the document; built in sources accept only `enabled`; ids come from `custom_from_seed(path, clock ms, counter)`; the removable drive hint is path based (`/run/media`, `/media`, `/mnt`, `/Volumes`, a non C drive letter) plus `FsProbe::volume_class`.
  - `scan::library_scan(ctx, LibraryScanRequest { full, level, workers }, &dyn ProgressSink, &CancelToken) -> LibraryScanResult { index: LibraryIndex, counts, diagnostics, timings, stats, sources, cancelled, game_version, manifest_before, manifest_saved }`: builds the source set from the selected install, workshop directories and custom folders and runs the library `Scanner` with the manifest cache; a mod found only in a custom folder is `NeedsLink`; a cancelled scan does not save the manifest; the result is not serialisable (the caller keeps `index`). Measured on the owner's machine: 763 mods, 744 loadable, 19 custom only mods flagged `NeedsLink`, 6 duplicate groups, full scan 1.17 s.
  - `ManagerError` with `manager.*` codes (wrapped errors keep their own code): `Store`, `Library`, `Cache`, `Path`, `SettingsInvalid`, `UnknownSection`, `UnknownKeys`, `ReadOnly`, `OverrideInvalid`, `FolderRejected`, `SourceNotFound`, `InvalidRequest`, `NoSources`, `Io`.
  - Not built yet (M2 and M3): sessions, sorting, profiles, history, datasets, duplicates reports in the UI, launch and bisect.
- **Internal dependencies** (0.1.0 manifest): `rimstudio-core`, `rimstudio-io`, `rimstudio-steam`, `rimstudio-library`; the other edges (`datasets`, `workspace`, `rules`, `sort`, `validate`, `ipc-types`) are added with the features that need them. The app converts engine types to DTOs.
- **External dependencies**: `nucleo-matcher` 0.3.1 (search; MPL-2.0 file level copyleft noted, fallback `strsim` 0.11.1), `alphanumeric-sort` 1.5.8, `strsim` 0.11.1, `serde_json` 1.0.151, `thiserror` 2.0.21, `tracing` 0.1.44.

- **Purpose**: the modding tools (R5, R7) as thin orchestration over workspace snapshots and engines.

Cancelled after at least one file it returns `Ok` with a `designer.apply-cancelled` warning and the written list; cancelled before the first file it returns `Err(Cancelled)`.

  - `registry::TOOLS` (static descriptors consumed by `rimstudio-app`); `ToolkitError` variants `PlanStale` (`designer.plan-stale`), `ApplyRefused` (`designer.apply-failed`), `PathRefused` (`project.path-outside-root`), `ProjectNotOpen` (`project.not-open`), `ProjectInvalid`, and wrapped `Workspace`, `Xml`, `Guard` errors that keep the engine codes.
- **Internal dependencies** (0.1.0 manifest): `rimstudio-core`, `rimstudio-io`, `rimstudio-xml`, `rimstudio-defs`, `rimstudio-design`, `rimstudio-workspace`, `rimstudio-library`, `rimstudio-ipc-types`; `rimstudio-validate` joins with the validation features.
- **External dependencies**: `serde_json` 1.0.151, `camino` 1.2.6, `blake3` 1.8.7, `thiserror` 2.0.21, `tracing` 0.1.44.
- **Features**: `tool-defs`, `tool-project`, `tool-designer` (all default on).

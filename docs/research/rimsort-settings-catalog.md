# RimSort settings catalogue

Scope: every persisted RimSort setting (global and per instance) with type, default, meaning and settings-dialog tab, so RimStudio can decide which to keep, rename or drop. Source: `RimSort-main/app/models/settings.py` and `RimSort-main/app/models/instance.py`; tab placement from `RimSort-main/app/views/settings_dialog.py` and `RimSort-main/app/controllers/settings_tabs/*`. Descriptions are our own wording. The table is generated by `docs/research/data/gen_rimsort_settings_table.py` from a cross-reference of attributes against the settings-tab controllers.

Status: research note | Last verified: 2026-10-04

## 0. How RimSort stores settings

- One JSON file (`settings.json`) in the platform user-data folder (platformdirs, `RimSort-main/app/utils/app_info.py`); a `DEBUG` marker file in the same folder, not a JSON key, turns debug logging on (`settings.py` load).
- Settings is a Qt object whose attribute setter emits a global "settings have changed" event on every actual change (`settings.py`, `__setattr__`), so every change fans out to listeners; there is no schema version, and migration is ad hoc (old flat path keys are folded into a "Default" instance on load, and an old SteamCMD folder is moved with a copy-then-delete).
- Secrets (Steam API key, Rentry code, GitHub token) are stored in plain text in the same file.
- The dialog has 9 tabs: Locations, Game Launch, Databases, Sorting, DB Builder, Internal Tools, External Tools, Appearance, Advanced (`settings_dialog.py`, `addTab` calls), plus Reset to Defaults, Cancel and OK buttons.
- Counts: 98 global attributes (script output), 13 per-instance fields.

Notes on the table:

- "Source mode" keys take one of four values: `None`, `Configured git repository`, `Configured URL` or `Configured file path` (a four-radio group per dataset, `settings_tabs/databases_tab_controller.py`). Five datasets (steamDB, community rules, NoVersionWarning, Use This Instead, RimWorld versions) each carry four keys: mode, local path, repo and archive URL. Repos are the ones RimSort ships as defaults; RimStudio must fetch equivalents at runtime and may not bundle them.
- The "no control found" rows are attributes that no settings tab references: either set from another widget (a search-bar toggle, an indicator) or leftovers. They are good candidates to drop or re-home.
- "Advanced / Databases layout": the widgets for backups, save comparison and mod list history are built in the Databases tab code region while the wiring lives in the advanced-tab controller (verify before copying the grouping).
- Window sizes are validated to 400-1600 px, falling back to 900x600 (`Settings.validate_window_custom_size`).

## 2. Per-instance settings

RimSort supports several named instances (default name `Default`); each is a record in `instances` (`app/models/instance.py`). The instance also owns a folder holding `aux_metadata.db` (notes, tags, colours, ignore flags) and SteamCMD data.

| Key | Type | Default | Meaning | Dialog tab |
|---|---|---|---|---|
| `name` | str | `Default` | Instance name | Instances menu |
| `game_folder` | str | empty | RimWorld install folder | Locations |
| `config_folder` | str | empty | RimWorld config folder (ModsConfig.xml lives here) | Locations |
| `local_folder` | str | empty | The single local mods folder | Locations |
| `workshop_folder` | str | empty | Steam workshop content folder (294100) | Locations |
| `run_args` | str | empty | Command-line arguments used when launching the game | Game Launch |

| `steamcmd_ignore` | bool | false | Set when the user answers "do not ask again" to the SteamCMD-not-installed prompt at startup | none (set by prompt) |

Observation for R3 and R4: RimSort models exactly one `local_folder` per instance. RimStudio requirement R4 (any number of custom mod folders) is therefore a structural change, not a setting tweak: use an ordered list of mod sources, each with a kind (game data, install Mods, workshop, custom), a label and an enabled flag.

Autodetect (Locations tab, "Autodetect" button) runs a per-OS path service for game, config and local-mod folders, warns when Steam is a Snap install, and fills the dialog fields; it covers one candidate per field and does not enumerate other Steam libraries (`controllers/settings_controller.py`, `_on_locations_autodetect_button_clicked`).

## Implications for RimStudio

1. Store settings as JSONC with an explicit `schemaVersion`, versioned migrations and atomic writes; never mutate files from a setter.
2. Split settings into three files with clear owners: app (UI, theme, language), workspace/instance (paths, mod sources, launch args), and secrets (OS keychain; fall back to a separate permission-restricted file). Never keep tokens in the main settings file.
3. Replace the single `local_folder` with `modSources[]` (kind, path, label, enabled, readOnly) and show them in one list with add, remove, reorder and "open" actions (R4).
4. Collapse the 20 dataset keys into one `datasets` table keyed by dataset id (`steamDb`, `communityRules`, `noVersionWarning`, `useThisInstead`, `rimworldVersions`) with `{source, url, localPath, lastFetched, etag}`; no per-dataset git repo keys (R6).
5. Emit fine-grained change events (key path) so only affected views recompute; settings changes must not trigger full list rebuilds.
6. Drop or re-home the no-control keys listed above; do not carry the deprecated alphabetical sorter unless the engine still needs it.
7. Window geometry is remembered automatically; do not expose 9 window-size keys. Keep launch state only if testing shows a need.
8. Provide "Import from RimSort" that reads the user's rules file and instance paths only; do not migrate secrets silently.
9. Every setting gets a search entry in a settings search box (RimSort has none, with 98 keys over 9 tabs).
